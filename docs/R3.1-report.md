# R3.1 report — shared native wire contract

Completed 2026-10-01. The native package, engineering frames and supervisor
dispatch descriptor now have explicit versioned layouts and independent
cross-language fixtures. This closes the contract step; no firmware download
endpoint or production loader is claimed.

## Implemented

- One machine-readable source, [`contract/wire.json`](../contract/wire.json),
  generates C/Rust offsets, sizes, IDs, limits and [layout tables](wire-layouts.md).
  Generation is deterministic; `--check` fails on stale checked-in outputs.
- A dependency-free `no_std` Rust crate and C11 header provide bounded byte
  readers, overflow-safe range checks, CRC-32/ISO-HDLC and CRC-16/CCITT-FALSE.
- [Normative semantics](wire-format.md) define exact compatibility, package
  coverage, canonical tags/bindings, transfer expiry/retries, response widths,
  error-only responses, capabilities, activation outcomes and snapshot pages.
- The maximum package is 19,024 bytes, with an 80-byte header and 40-byte tags.
  Only its payload, at most 16 KiB, belongs in the code slot. The descriptor
  occupies 16 bytes at input-region offset 256; it is supervisor-owned.
- Checked-in golden bytes cover A/B packages, the descriptor, nine request and
  success pairs, UNSUPPORTED, and a 240-byte chunk. Package fixtures contain
  four illustrative Thumb bytes and three tags, not compiler-produced logic.

The first profile retains fixed-slot host linking, no imports/device fixups,
zero initial state, unsigned local-lab opt-in, explicit ABI/target revision and
no user-supplied peripheral addresses. Optional rollback and VAR-write commands
have layouts but cannot be advertised until their implementations exist.

## Verification

Passed `make test` with LLVM on PATH, including all existing compiler/native
semantic, legacy oracle, ABI and sanitized scan/exception tests. New checks:

- Five wire test groups independently consume frozen fixtures in C and Rust,
  compare CRC results against Python standard-library implementations, and
  check explicit response formats against the shared field definitions.
- Both consumers reject truncated/oversized frames, bad CRCs, inconsistent
  totals, section overlap, zero/oversized tag counts, invalid record widths,
  odd/out-of-text entries and overflow-prone offsets/lengths. The C consumer
  runs under AddressSanitizer and UndefinedBehaviorSanitizer.
- Descriptor tests reject missing Thumb state, firmware addresses, invalid
  counts/generations, nonzero reserved bytes and truncation.
- Rust primitive tests check published checksum vectors, little-endian reads,
  exact-end ranges and integer-overflow boundaries.

Reproduce without downloading packages:

```sh
make test-wire
cargo test --workspace --locked --offline
make test
```

Golden fixtures are not regenerated by tests. Their explicit byte recipes and
expected values are independent of generated offsets; changes require review
as compatibility changes, not automatically accepting new snapshots.

## Limits and next task

The fixture consumers are **test-only envelope checkers**, not a full package
validator. They do not establish target/schema acceptance, slot ownership,
streaming resynchronization, timeout behavior or device execution. The current
board gateway still has its static entry/count; it does not read the descriptor
yet. No board flash or hardware test was needed for this host-only change.

Next is **R3.2**: bounded C package validation and staging, separate metadata/code
storage budgets, slot reservations, CRC/compatibility/schema rejection tests,
and a Rust packager that obtains tags from compiler output. UART transport and
boundary activation follow; online migration/rollback remain R4.
