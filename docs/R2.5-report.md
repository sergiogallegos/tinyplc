# R2.5: physical I/O and scan supervision

Implemented and exercised on 2026-10-01. The C runtime now owns the scan
transaction, fault latch and output policy. The static FreeRTOS task samples
PC13, invokes ABI 2 ST code from RAM, commits PA5 on success and records scan
and release timing. [Design and limits](scan-runtime.md).

## Evidence

The connected board identified as STM32F446, 512 KiB flash. Both firmware
images were flashed and verified through ST-LINK. Each automatic test took
two halted observations separated by approximately one second of execution.

| Observation | Button/LED image | Division-fault image |
| --- | ---: | ---: |
| Scans in two samples | 109 → 210 | 109 → 210 |
| Native status | 0 | 5 (division by zero) |
| Committed N | 0 | 0 |
| Committed LED and PA5 output latch | 1 | 0 |
| PC13 / BTN | 1 / 0 | 1 / 0 |
| Largest observed scan interval | 378 cycles / 23.625 µs | 266 cycles / 16.625 µs |
| Observed release period range | 159,997–160,213 cycles | 159,997–160,213 cycles |
| Largest release deviation | 213 cycles / 13.3125 µs | 213 cycles / 13.3125 µs |
| Missed releases | 0 | 0 |
| Free task-stack words | 474 / 512 | 474 / 512 |

The fault fixture attempts LED=TRUE and N=123 before dividing by zero. Neither
value commits; later scan releases continue with outputs off. The normal
firmware was restored after that test. Both runs had a zero assertion latch,
probe result 42 and enabled MPU with privileged-only peripheral access.
These are short observations at nominal HSI frequency, affected by debugger
halts, not WCET proofs, calibrated physical timing or fault-response bounds.
The reported scan interval excludes stack diagnostics and scheduler overhead.

Filtered logs and exact ELF hashes: [GPIO](evidence/R2.5-gpio.txt),
[fault](evidence/R2.5-fault.txt). The automated normal run observes the released
button only. The user confirmed that B1 turns LD2 off while pressed and back
on when released. The first later debugger capture still had zero button
counts, so it was not accepted as press evidence. On a requested repeat without
reset, the runtime recorded **two transitions and N=187**, with LED=1 after
release, status=0 and no missed releases. Scans advanced 14,706 → 14,807;
the largest observed scan interval increased to 381 cycles (23.8125 µs).
[Button press/release evidence](evidence/R2.5-button.txt).

Current link usage: 15,736 B privileged flash, 440 B syscall veneer flash,
4,888 B privileged RAM, 192 B code-A contents, plus the existing reserved
code-B, input, working and task-stack regions. The overflow-negative link
check, section permissions, handler vectors and RAM entry checks passed.
Host scan tests run with ASan/UBSan; full compiler/ABI/oracle regression also
runs under `make test`.

## Reproduce

Use the pinned local tools described in [setup](setup.md) and
[memory layout](memory-layout.md). Set LLVM tools on PATH first.

```sh
make test
make target-build target-verify FREERTOS_ARCHIVE=/tmp/tinyplc-kernel.tar.gz \
  ARM_PREFIX=/tmp/tinyplc-arm-gcc/bin/arm-none-eabi-
python3 scripts/board_check.py --flash
/tmp/tinyplc-openocd/bin/openocd -f interface/stlink.cfg \
  -f target/stm32f4x.cfg -f build/native/board-check.tcl
```

For the fault experiment, build with
`python3 scripts/build_target.py --kernel-archive /tmp/tinyplc-kernel.tar.gz --gcc-prefix /tmp/tinyplc-arm-gcc/bin/arm-none-eabi- --source tests/scan/fault.st`,
then generate the test with `python3 scripts/board_check.py --flash --expect-fault`
and run OpenOCD as above. Restore the default build and flash afterward.
`--observe` reads the current firmware without resetting its counters; use
only when its symbols match the running image. The build never flashes by
itself; the generated OpenOCD script with `--flash` does.

The task remains privileged. Downloadable images, monitoring, native abort,
watchdog recovery and online change remain later tasks. Next is R2.6: separate
user privilege and memory, establish protected return/abort and inject memory,
stack and nontermination faults under an independent deadline guard.
