# R2.4: ST → Rust → LLVM → RAM execution on STM32

Completed during 2026-09-30–2026-10-01 as a privileged native-code experiment. The Rust compiler
now emits native ABI 2 with `--abi 2`, preserving default ABI 1 behavior.
Both interfaces use the same typed IR and arithmetic rules. ABI 2 reads INPUT
indices from its separate input base, uses working state for OUTPUT/VAR cells,
requires an exact count and leaves physical fault policy to the supervisor.

## Host and artifact evidence

Passed: nine Rust tests, Clippy with warnings denied, 11 LLVM integration tests
including 109 programs per ABI × three scans × O0/O2 = 1,308 native comparisons
against the independent Python/C oracles. Tests also cover separate bases,
input preservation, exact count, diagnostics and supervisor commit/discard.
The independent C/LLVM ABI fixture remains in `make test-abi`.

The board build compiles `examples/button_led.st` through Rust and LLVM,
then links its object into SRAM1 code A alongside the small RAM probe.
`tinyplc_scan` is linked at 0x20010004; code and metadata occupy 192 bytes
including the four-byte probe. User object imports are empty; its ARM exception
index relocation is resolved by the static firmware link. There is no dynamic
relocator or downloadable package. No unresolved symbols remain in the ELF.

Current build: 15,072 bytes privileged flash, 440 bytes veneer flash and 4,720
bytes privileged RAM, plus reserved slots, I/O buffers and stack. The linked
ELF has a non-executable GNU_STACK declaration; hardware permissions still
come from MPU configuration. Section/vector checks and a deliberate input
region overflow rejection passed.

## Board observations

User authorized flashing and hardware testing. ST-LINK reported an STM32F446
ID register of 0x10006421 and 512 KiB flash. OpenOCD programmed and verified the
ELF, reset it, then sampled execution twice with one-second run intervals.
The privileged task repeats synthetic BTN inputs `0,1,1,0,0`; it independently
checks each compiled result before committing it. Physical LD2 remains off.

| Observation | First sample | Second sample |
| --- | ---: | ---: |
| Completed scans | 109 | 209 |
| ST counter N | 44 | 84 |
| ST output LED (memory value) | 1 | 1 |
| Free task-stack words | 480 / 512 | 480 / 512 |
| Largest observed instrumented call interval | 52 cycles | 52 cycles |

RAM probe returned 42, assertion latch and native status stayed zero, MPU
control was 0x5, and the general-peripheral RASR was 0x11000039 (privileged RW,
execute-never). At the nominal 16 MHz reset clock, 52 cycles is 3.25 microseconds.
This is a sampled interval including instrumentation, not a WCET bound or a
whole-scan deadline measurement. Debugger halts affect scheduling observations.
[Filtered board log and exact ELF SHA-256](evidence/R2.4-board.txt).

The first ST-native board run exposed an input-map bug: AP=read-only denied
supervisor writes too. MemManage reported CFSR=0x82 and MMFAR=0x20018000. Changing
the input region to privileged RW/unprivileged RO fixed it; the subsequent
full flash/verify/run check passed. This is evidence of one MPU behavior, not
an adversarial isolation test.

## Reproduction and boundaries

See [memory-layout.md](memory-layout.md) for build/board commands. Tools were
extracted into temporary storage, with no global install. For hardware access
we used xPack OpenOCD v0.12.0-7, reporting
`0.12.0+dev-02228-ge5888bda3-dirty`, not pristine upstream 0.12.0. Its archive
checksum and provenance are recorded in the target lock; the upstream source
download failed and the binary distribution linked by OpenOCD was used instead.

The task is privileged and inputs are synthetic. This is not yet an isolated
user task, physical I/O scan, independent deadline guard, runtime loader,
engineering monitor or online change. The board is left running this experiment.
Next: R2.5 physical input/working/output supervision and measured scan timing;
R2.6 adds unprivileged containment and fault recovery.
