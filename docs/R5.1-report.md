# R5.1 acceptance — native TON and TIME

Implemented 2026-10-02 after checkpoint `23d4572` was committed and pushed to
`main`. This extension adds the requested TON on-delay function block, TIME
literals/variables/comparisons, native lowering, clock binding, package/monitor
support, and explicit restart-on-update semantics. The complete language and
runtime contract is [ton.md](ton.md); a button-to-delayed-LED example is
[ton_led.st](../examples/ton_led.st).

## Host acceptance

`make test ARM_PREFIX=/tmp/tinyplc-arm-gcc/bin/arm-none-eabi-` passed, including
all existing compiler, LLVM, historical bytecode, ABI, scan, frame, wire, loader,
and engineering tests. The dependency-free Rust frontend has new rejection
checks for invalid arguments, types, members, durations, reserved names, and
expanded capacity. The 64-cell limit includes the shared clock and timer cells.

[TON execution tests](../tests/llvm/test_ton.py) assemble and verify LLVM IR,
execute actual generated machine code at O0/O2, and cross-compile ARM code.
They cover rising/falling edges, irregular sample intervals, equality at PT,
zero delay, reset/rearm, 32-bit clock wrap, saturation, changing PT, skipped
calls, repeated calls, independent instances, invalid TIME, and fault atomicity.
A seeded 1,000-step sequence at each optimization level agrees with an
independent start-time reference model.

The actual packager's timer image passes the C validator. Invalid TIME/clock
binding combinations, unknown types/classes and duplicate clock bindings are
rejected with recomputed CRCs. Existing wire golden fixtures stay unchanged.
Update tests prove TIME VAR migration and TIMER reset during activation,
explicit rollback, and automatic recovery after a failed trial. Runtime scan
tests reject overflowing candidate TIME values without committing timer state.
The existing update/snapshot concurrency suites pass as part of `make test`.

## Target acceptance

Built and verified with the pinned GCC 13.3.1 and FreeRTOS archive:

```sh
make target-build target-verify \
  FREERTOS_ARCHIVE=/tmp/tinyplc-kernel.tar.gz \
  ARM_PREFIX=/tmp/tinyplc-arm-gcc/bin/arm-none-eabi-
python3 scripts/test_ton_board.py --device /dev/cu.usbmodem2103 \
  --gcc-prefix /tmp/tinyplc-arm-gcc/bin/arm-none-eabi-
```

The explicit script flashes the firmware, downloads native packages, tests
TON through the engineering CLI, and resets to the normal boot program in
`finally`. Recorded [board evidence](evidence/R5.1-ton-board.json) includes the
source programs, firmware/package SHA-256 identities and monitor/status data.
The [debugger sample](evidence/R5.1-ton-debugger.txt) records timing and stacks.

The exercised program calls a 500 ms timer with a deterministic high/low/high
input sequence. Coherent monitor snapshots verify waiting, completion, reset,
rearm, and agreement between ET and frozen clock differences. A same-schema
activation preserves its scalar counter but restarts the timer; rollback
restores the saved counter and restarts the timer again.

A second program fills all 64 cells: twelve independent timers, LED, N, PT,
and the shared clock. All twelve ET readings agree in a single paginated
snapshot, demonstrating common frozen time across instances. Its package is
6,536 bytes, including 3,896 payload bytes and 2,560 schema bytes plus the
80-byte header. The ordinary timer exercise package is recorded in the evidence.

| Measurement | Observed result |
| --- | --- |
| Scans before debugger sample | 850 (about 8.5 s at the 10 ms release period) |
| Maximum complete scan body across activation, monitoring and both programs | 68,513 cycles = 4.2820625 ms at 16 MHz |
| Last native scan transaction in the 12-timer program | 1,460 us |
| Maximum native scan transaction across the run | 2,867 us |
| Missed releases / native faults / assertions / UART errors | 0 / 0 / 0 / 0 |
| Supervisor stack free | 438 words = 1,752 bytes |
| Worker stack free (12-timer program) | 464 words = 1,856 bytes |
| Comms stack free | 928 words = 3,712 bytes |
| Privileged RAM allocation | 58,740 bytes, unchanged |
| Extra static headroom after mandatory 4 KiB MSP reserve | 2,700 bytes |

Measured scan-body timing includes trusted work and is distinct from the
narrower scan-transaction telemetry. Debugger halt occurs after the measured
window; normal boot is restored afterward (generation 1, no pending update,
fault 0, missed releases 0). These are observations of this bounded lab run,
not a worst-case execution-time proof. Host clock-wrap and saturation tests do
not imply multi-day hardware soak testing.

R5.1 is accepted for the educational native profile. Remaining limits include
the documented TIME/literal subset, reset-only timer state across online
changes, no persistent timers, no runtime imports, and no general function-block
library. Older firmware rejects TON schema IDs and must be updated first.
