# R3.4 — owned tag snapshots and bounded monitor reads

Implemented on 2026-10-02. The portable runtime, STM32 adapter and `plctool
DEVICE monitor` now implement the existing READ_TAGS contract. Host sanitizer,
concurrency and serial-simulator evidence is recorded below. Hardware execution
and whole-scan timing under simultaneous download/monitor load remain R3.5.
No board was flashed for this report.

## Ownership and lifetime

`runtime/src/snapshot.c` owns three complete buffers. Every publication copies
up to 64 tag records, including names, types, bindings and values, alongside the
active generation and completed scan ID. There are no borrowed schema/state
pointers in a published snapshot. The STM32 adapter takes input values from the
frozen input image and output/internal values from committed state, including
forced-zero outputs after faults. The boot schema is copied from compiler-exported metadata before its slot can
be reused; downloaded generations use the active loader schema.

One scan producer owns the back buffer, one comms consumer owns the front
buffer, and a C11 atomic index owns the middle buffer. Acquire/release exchanges
transfer exclusive ownership. The producer can replace unread publications
indefinitely using two buffers even while the consumer retains its third
buffer. There is no reader lock, refcount, allocation, scan-side waiting, or
interrupt masking around record copying. A compile-time assertion requires
lock-free integer atomics. The F446 build links without atomic helper imports.
The API requires exactly one producer and one consumer, initialized before tasks.

A request for scan zero starts an enumeration. Continuations must match its
generation and scan. Each response contains at most five tags (216 payload
bytes), with a shorter final page. The last page or 2,000 ms inactivity ends the
logical lease. The consumer may physically retain its buffer after expiry;
this never prevents publication. A new enumeration acquires the latest
available buffer. A new start replaces any previous enumeration. Stale tokens
return BUSY, invalid counts/indices return BAD_REQUEST, and no first publication
returns NO_PROGRAM. Generation/scan identities are scoped to a controller boot.

The CLI fetches all pages before printing JSON, checks page widths, identity,
indices, total count and tag metadata, and emits BOOL as booleans and DINT as
signed integers. It performs one enumeration per invocation and returns an
error if the lease expires or pages disagree. It does not combine partial
snapshots. INFO advertises READ_TAGS only when a mailbox is wired.

## Reproducible validation

```sh
make test ARM_PREFIX=/path/to/bin/arm-none-eabi-
make test-snapshot-thread
make target-build target-verify \
  FREERTOS_ARCHIVE=/path/to/kernel.tar.gz \
  ARM_PREFIX=/path/to/bin/arm-none-eabi-
```

`make test-engineering` runs AddressSanitizer/UndefinedBehaviorSanitizer tests:

- A pinned reader survives 9,998 newer publications and destruction of source
  names/values, then reads its original generation/scan coherently.
- Invalid requests, wrong generations, invalid indices, expiry across the
  32-bit clock wrap, short final pages and released tokens are checked.
- A concurrent producer publishes 100,000 changing schemas/generations while
  the reader performs 10,000 complete 64-tag enumerations. Every returned name
  and value is checked against the captured identity.
- The POSIX serial simulator exercises download, lost-chunk-ACK retry,
  activation and a 13-page CLI enumeration, including BOOL and negative DINT.

The same concurrent stress passed ThreadSanitizer with no race reports.
Target build, linker bounds, protected gateway checks and A/B placement tests
passed using the pinned GCC 13.3.1 and FreeRTOS archive. Target memory usage:

| Region/object | Bytes |
| --- | ---: |
| Privileged flash | 25,984 / 65,536 |
| Call flash | 528 / 4,096 |
| Privileged RAM | 58,428 / 65,536 |
| Three-buffer mailbox | 7,752 |
| Input/committed merge scratch | 256 |
| Owned boot schema | 120 |

GCC reports static stack frames of 24 bytes for publication, 40 for paged
reading and 48 for the board snapshot adapter; these are per-function compiler
estimates, not measured task high-water marks. Snapshot publication is included
in `scan_cycles_max`; status packing, stack probes and scheduler blocking remain
outside that counter. R3.5 must measure the complete scan and release behavior
on hardware with monitoring and downloads active.
