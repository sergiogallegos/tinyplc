# R2.6: unprivileged execution, deadline abort and reset recovery

Completed on 2026-10-01 on the connected NUCLEO-F446RE. The firmware now uses
a privileged scan task and a separate unprivileged ST worker, with distinct
stacks, MPU permissions, a checked return-only SVC gateway, TIM2 deadline
interrupt and IWDG fallback. The native ABI and portable transaction remain
unchanged. [Design, code links and reproduction commands](native-isolation.md).

## Final board matrix

All **19 cases passed** on the final implementation. Device ID/flash checks
identified an F446 with 512 KiB flash. Each programmed ELF was verified before
execution. For adversarial assembly fixtures, the first scans drove PA5 ON and
committed N=1..3; the fourth scan dirtied working N to 999 before attempting the
violation. Contained faults kept committed N=3, forced PA5/LED=0, suspended the
worker and continued periodic safe-state supervision. Reset cases booted with
N=0, outputs off and user execution disabled.

| Cases | Observed outcome |
| --- | --- |
| Privileged RAM write/read, frozen-input write, code write, GPIO write, stack-guard write | MPU data faults, status 259, CFSR 0x82 |
| Execute working data or supervisor flash | Instruction-access fault, status 259, CFSR 0x1 |
| User FP instruction | NOCP usage fault, status 259, CFSR 0x80000 |
| SVC raise-privilege, scheduler-start and forged return | Gateway rejection, status 260 |
| Infinite execution and attempted interrupt masking | TIM2 abort, status 258; supervisor remains alive |
| Stack moved below mapped stack, outside stack, or into read-only code | Watchdog reset, boot status 261, retained stacking fault CFSR 0x10 |
| Rust/LLVM-generated division-fault ST | Normal checked return carrying fault 5; candidate LED=TRUE and N=123 discarded |
| Rust/LLVM-generated button/LED ST | 122 successful entries/returns at sample, status 0, no missed releases |

The gateway observed CONTROL.nPRIV=1 on normal and contained-fault executions.
The normal image was restored after the matrix and left running. The button
polarity was already physically confirmed in R2.5; this turn did not ask for a
new manual press test.

actual artifacts. `build/isolation/final-board.log` retains the full local tool

## Timing and memory observations

At nominal 16 MHz HSI, the normal image's largest instrumented scan interval
was **2,181 cycles = 136.3125 µs**. This includes input acquisition, dispatch,
worker execution, gateway/notification switches, physical output commit and
state publication; it excludes stack-watermark probing and final scheduler
blocking. Normal supervisor stack free space was 454/512 words, worker space
502/512 words. These high-water samples are not worst-case stack proofs.

Infinite-loop and interrupt-mask tests entered the deadline handler at
160,237 cycles from scan start. The safe-output write/barrier completed 23
cycles later: **160,260 cycles = 10.01625 ms**. They each recorded one missed
release and then stayed faulted without catch-up user executions. The timer
setup and IRQ latency therefore must not be described as an exact 10.000 ms
output bound. The tested fault-handler timestamp-to-output intervals were
12–25 cycles, depending on path; they exclude earlier instruction/exception
entry latency and are not oscilloscope measurements of an external load.

Each watchdog case had reached healthy fault-latched supervision by the
1.2-second post-injection observation, with IWDGRSTF set and retained frame
metadata. The configured nominal watchdog timeout is about 0.5 s; exact reset
latency was not independently measured. OpenOCD freezes watchdogs while halted;
the reset tests explicitly resumed execution. All measurements are short lab
observations, not WCET, oscillator calibration or safety certification.

Final normal linker reservations used: 18,636 B privileged flash, 480 B
system-call flash, and 10,508 B within privileged RAM (including alignment,
private stack and retained diagnostics). Code A contains 228 B of probe,
compiled code/metadata and trusted trampoline. The existing 16 KiB inactive
slot, 512 B inputs, 512 B working region and 2 KiB user stack remain reserved.
MSP retains a separate 4 KiB budget inside privileged RAM.

## Verification and integration findings

Passed: full `make test` (nine Rust tests, 11 LLVM integration tests including
1,308 differential native comparisons, historical runtime tests, C/LLVM ABI
fixture, sanitized scan transaction tests and new exception-frame boundary
tests), Rust formatting/Clippy, and Python script syntax checks. ELF verification
checks the custom SVC/fault/TIM2 vectors, unchanged PendSV/SysTick bindings,
separate stack placement, retained-data bounds, RAM entry/trampoline locations
and intentional overflow rejection.

Hardware bring-up exposed three issues, corrected before the final matrix:

1. TIM2's software update event could arrive after UIF was cleared, causing a
   false deadline before the worker ran. Initialization now waits for the event.
2. Handler-mode CONTROL.SPSEL reads zero. Requiring the thread-mode value
   rejected legitimate frames; EXC_RETURN now establishes PSP provenance.
3. SVC could reject a corrupted stack before its pending stacking fault handler
   ran. Reset fallback now captures hardware CFSR itself, preserving the real
   stacking-fault evidence instead of an empty software diagnostic.

The watchdog is fed after healthy supervisor cycles, including safe,
fault-latched cycles. This deliberately preserves diagnosability rather than
repeatedly resetting on every ordinary user fault. Nonreturning supervision and
unsafe exception contexts stop feeding it. No communications task exists yet.

## Remaining scope

R2.6 is an educational fixed-three-tag board integration. No native image
package, download protocol, loader, concurrent monitor or online change exists.
The trusted trampoline currently shares the immutable statically linked RAM
slot; R2.7 must reserve it outside downloadable payload ownership. R2.7 also
finalizes placement, package compatibility and lab authenticity policy. R3
then implements upload/accept/monitor, and R4 implements migration/rollback.
The tests are evidence for these specific paths, not proof of a complete
security boundary or industrial functional safety.
