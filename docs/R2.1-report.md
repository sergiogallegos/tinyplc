# R2.1: target call ABI draft and fixtures

Completed 2026-09-30. [Native ABI draft 2, revision 1](native-abi.md) specifies
Thumb/base AAPCS32/soft-float, four entry arguments, fixed tag cells, separate
input/working buffers, diagnostic layout, status codes, supervisor commit and
fault responsibility. The first profile permits no runtime service imports.
An explicit comparison explains the change from R1's single-buffer ABI.

The C header is `runtime/include/tinyplc/native_abi.h`. Static assertions cover
diagnostic size/alignment/offset; target builds also check data/function pointer
width. A handwritten LLVM fixture and C caller exercise the interface at O0
and O2, including repeated scans, exact count rejection, input preservation,
division diagnostics, wraparound and rejection of a dirty failed candidate.
Both files cross-compile as little-endian ARM ELF32 objects.

Validation: `make test-abi` passed with installed LLVM/Clang 23.1.2 and Python
3.14.7 on macOS arm64. Documentation local links and `git diff --check` passed.
No executable compiler/runtime behavior was changed; the new fixtures do not
claim the compiler emits ABI 2. R1's ABI and golden outputs remain unchanged.

No FreeRTOS integration, native image loader, MPU enforcement, privilege-return
mechanism or hardware execution is implemented here. The fixture's small
caller is not a reusable PLC supervisor. C const alone is not memory protection.

Next task: R2.2 toolchain and MPU-aware port selection. Compiler ABI 2 emission
and full semantic regression are required before the ST-generated board
experiment. Memory placement and the native package remain subsequent gates.
